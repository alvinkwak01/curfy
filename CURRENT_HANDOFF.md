## What is implemented in current code
### Premium integration
- Settings fetches Apple's localized non-consumable price, offers explicit purchase and restore, and handles pending/cancelled/unavailable ownership. Purchase/restore cannot overlap. No cloud account prerequisite.
- Settings accepts multiple apps only after a fresh native StoreKit entitlement check at configuration. Categories/websites remain rejected. Onboarding remains one-app.
- Home repeats its existing native-label row per app. Route carries only native selection revision/index; the hold screen prepares a private native singleton ticket. A missing/stale choice cannot start a multi-app hold. The ring and single-X screen design are retained.
- SleepContext invokes singleton Premium grant only after HoldButton completion; Free grant still insists on exactly one app. Premium does not set Free's global access cooldown.
- All native JS operations share a guard against concurrent grants/configure/stop. Foreground reconciliation avoids mutating native state while an operation is pending.
- Multi-app foreground repair subtracts active exception selections using the installed library's native `difference` API with `stripToken:true` and native persistence; it never needs app names or tokens in JS. It verifies per-app state and does not momentarily re-shield active exceptions.
- Stop retires Premium one-shot monitors before daily cutoff. Refused stops restore callbacks and retain recovery. Failed schedule replacement restores original selection/window and original exception deadlines. One Premium hold cannot authorize editing every other protected app: all selected apps need their own active exception, or the window must end.
- Grants verify daily monitor, committed selection and clock before/after asynchronous registration. Missing per-app monitor is not treated as valid access. Swift callbacks verify the daily monitor and committed group; delayed starts only honor exceptions with a reblock monitor or a cutoff-owned expiry.

### Leaderboard consent
- Unknown/declined/unreadable consent prevents signup/profile writes, including legacy sessions. Joined state is persisted/read back before upload.
- The approved disclosure appears after completed onboarding, before first upload; no onboarding screens changed. Settings can join/leave/retry.
- Leaving persists `leaving`, immediately pauses new uploads, drains in-flight profile work, deletes the cloud identity through existing authenticated deletion, then records `declined`. Failed cloud removal remains visibly retryable. Local history, journal, Screen Time and Premium survive leaving.
- Auth deletion now reads the current session after pending signup settles; a withdrawal during signup cannot orphan a new profile.
